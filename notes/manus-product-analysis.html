Part 1 · Agent 是什么 & 什么时候该用/不该用

—— 写给非技术背景的产品经理

一、Agent 不是什么玄学，是 Chatbot 的进化版

很多人第一次听到 AI Agent，觉得是个高大上的概念。但如果用一句话说清楚，就是：Chatbot 只能聊，Agent 能干。

ChatGPT、Kimi、Claude.ai 这一类是 Chatbot。你问它"帮我写一篇周报"，它给你一篇文字。但你需要手动复制、粘贴到其他工具、自己配图、自己发邮件。

Manus、Devin 这一类是 Agent。你对它说"帮我做一份竞品分析，整理成 PPT 发我邮箱"，它自己会：搜索网页 → 整理数据 → 做图表 → 生成 PPT → 发邮件。全程不需要你管。

区别的核心只有三个字：主动权。Chatbot 等人喂。Agent 自己动手。

二、Agent 的三个器官：大脑、手脚、记忆

一个成熟的 AI Agent，有三个必备组成部分：

  • 大脑（LLM） — 思考和规划。比如"用户要做竞品分析"→ 拆成：搜资料、读文章、整理表格、画图表、写结论。
  • 手脚（Tool Use） — 执行行动。浏览器搜索、Python 计算、读写文件、调 API。没有手脚，Agent 就是个思想者。
  • 记忆（Memory） — 上下文感知。短期记忆（当前对话）让 Agent 知道你在说什么；长期记忆（向量库/文件）让 Agent 记住你的偏好和历史。
💡 Agent 的工作循环（ReAct 范式）：
思考 (Thought) → 行动 (Action) → 观察 (Observation) → 再思考 → 再行动 → …… → 完成
每轮循环就是一次"想→做→看结果→再想"的过程，直到任务完成。

三、什么时候该用 Agent？

✅ 适合用 Agent 的场景：

  • 多步骤但明确的任务 — 比如"调研 5 个竞品，生成对比表"。每个步骤（搜索→提取→整理）是确定的，但需要组合执行。
  • 需要调用多种工具 — 搜索 + 代码 + 文件操作，人在中间切换工具很烦，Agent 可以无缝衔接。
  • 容忍异步等待 — Agent 跑一个复杂任务可能需要 5-30 分钟。如果你能先丢任务、后收结果，Agent 很适合。
  • 重复性工作 — 每天/每周都要做的固定流程（日报生成、简历初筛、数据报表），用 Agent 自动化最划算。

❌ 不该用 Agent 的场景：

  • 单步就能完成的 — 问"今天天气怎么样"用 Chatbot 就够了，不需要 Agent。
  • 需要精确控制的 — 每一步都要人工审批、调整参数，用 Workflow（流程自动化）比 Agent 更适合。Agent 会自作主张。
  • 实时交互的 — 用户在聊天框里等回复，Agent 跑 5 分钟会让人抓狂。这种情况应该用 Copilot 模式（人+AI 实时协作）。
  • 成本敏感且高并发的 — Agent 每个步骤都调 LLM，成本是 Chatbot 的 5-10 倍。量大的场景要算清楚账。
  • 确定性要求极高的 — 法律文书、医疗诊断等场景。Agent 的每步都有概率出错，5 步后准确率可能跌到 60%。人必须全程盯着。

四、Agent × Chatbot × Workflow × Copilot 的判断矩阵

这是 AIPM 最基础的选型判断工具（来自模块2的框架）：

  • 任务确定性高 + 步骤单 → Chatbot（一问一答）
  • 任务确定性高 + 步骤多 → Workflow（预定义流程）
  • 任务确定性低 + 用户需要实时介入 → Copilot（人机协作）
  • 任务确定性低 + 可异步等待 → Agent（自主执行）

Manus 处于"任务确定性低 + 可异步等待"这个象限。你把一个模糊的目标（"帮我研究一下这个行业"）丢给它，它自己去拆解、执行、交付。

Part 2 · Manus 产品深度拆解

产品架构图

基于公开信息与社区分析的 Manus 系统架构推测

产品基本信息

  • 产品名 Manus
  • 公司 Monica.im（蝴蝶效应），创始人肖弘（Peak）
  • 发布时间 2025年3月6日正式面向全球开放
  • 定位 通用 AI Agent — 「首个通用AI助手」
  • 定价 当前免费有配额（每日限任务数），Pro 版本传闻 $19.9-39.9/月
  • 运行模式 Web 端提交任务 → 云端后台异步执行 → 实时流式输出过程 → 交付成品

核心能力拆解

1. 任务规划（Planning）

用户输入一个模糊目标（"分析特斯拉2026年Q1财报"），Manus 自动拆解为子任务：搜索财报原文 → 提取关键指标 → 计算同比变化 → 分析市场反应 → 整理成报告 → 生成图表。每一步都在规划列表中展示，用户可以看到它在做什么。

2. 多工具执行（Tool Use）

Manus 能并行使用多个工具：浏览器（Chromium 沙箱）做网页搜索和信息提取；代码沙箱（Python/Node.js）做数据计算和分析；文件系统做读写、格式转换（Excel/PPT/PDF）；MCP 协议对接第三方 API。

3. 多模型混合

不绑定单一 LLM。简单任务用小模型（便宜快速），复杂推理用大模型（Claude、GPT-4o），在不同的子任务间根据特性切换模型，降低成本同时保证质量。

4. 云端异步执行

任务提交后用户可以关闭浏览器离开，完成后通过通知或下次登录查看结果。每次任务最长 30 分钟。

5. 结果交付

不是"给你一段文字"，而是直接生成可交付的成品：HTML 报告、Excel 表格、PPT 演示稿、PDF 文件。产出感强。

竞品对比（AIPM 视角）

  • Manus vs Devin — Devin 专注编程，深度更好但泛用性差（$500/月）。Manus 更通用，价格更低（目前免费），但编程深度不如。定位差异：Devin 是"AI 工程师"，Manus 是"AI 助理"。
  • Manus vs Claude Code — Claude Code 是终端内实时协作的编程 Agent（你敲命令它干活），人机交互更紧密。Manus 是后台异步执行，全自动化。一个适合开发者日常工作，一个适合一次性复杂任务。
  • Manus vs 扣子空间/扣子 — 扣子是 Agent 搭建平台（让你自己搭 Agent），Manus 是成品 Agent（直接用）。一个是工具平台，一个是最终产品。
  • Manus vs ChatGPT Tasks — ChatGPT Tasks 是轻量级定时任务，Manus 是重量级自主 Agent。复杂度不在一个量级。
💡 AIPM 视角的关键思考：Manus 的产品定位是"让 AI 从助手变成员工"。它的核心价值不是技术多强，而是降低了使用 Agent 的门槛——用户不需要了解 Prompt、不需要配置工具链，像用 ChatGPT 一样说一句话，就获得了一份成品。

已知问题与风险

  • 成本高 — 每次任务约 $0.5-2 的推理成本，免费模式难持续。
  • 排队时间长 — 高峰期需等数小时。
  • 任务失败率 — 部分复杂任务中途失败，缺乏自动重试机制。
  • 隐私风险 — 数据上传云端沙箱，不适合敏感信息场景。
  • 不可重复性 — 相同输入可能不同输出，难以调试。
  • "套壳"争议 — 被质疑只是封装了其他模型和工具，技术壁垒不强。

AIPM 视角的总结思考

Manus 是一个教科书级的 Agent 产品案例，原因如下：

  • 它完整展示了 Agent 的 ReAct 范式（思考→行动→观察→再思考）在实际产品中的落地
  • 它的 用户价值很清晰："说一句话，拿到成品"——这个价值主张在面试里能一句话讲清楚
  • 它的 商业模式困境（成本高、难盈利）是整个 AI Agent 行业的缩影，适合用来讨论"AI 产品为什么难赚钱"
  • 它的 "套壳"争议 引发了一个好问题：AI 产品的壁垒到底是什么？是模型能力、数据飞轮、用户习惯，还是生态绑定？
💡 如果面试官问"你怎么看待 Manus"，一个能加分的回答结构：
① 先说产品定位（通用 Agent，降低使用门槛）
② 再说核心设计亮点（多模型路由、异步执行、成品交付）
③ 然后说问题（成本、隐私、不可重复性）
④ 最后给建议（付费模式优化、私有化部署、企业版场景聚焦）
—— 这就是 AIPM 的思考方式：从产品到商业，再到改进方向。
