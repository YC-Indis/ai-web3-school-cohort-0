# 像素酒馆 · 产品需求文档

## 一句话概念

> 剑与魔法世界的像素酒馆。你是吧台服务员，各地来的客人推门进来找你聊天。你用英语招呼他们、听他们的故事——每次开口都在学英语。

---

## 一、用户角色

**你 = 吧台服务员**
- 你的任务：招呼客人、点单、聊天、听故事
- 你的第一件事就是开口说英语——没有沉默的选项
- 你的英语越好，能解锁的故事线越深

**NPC = 推门进来的客人**
- 矮人矿工：沉默寡言，心事重重
- 精灵信使：优雅礼貌，说话混英语单词
- 旅行商人：话多爱聊，语速快
- （后续可扩展更多角色：骑士、法师、盗贼……）

---

## 二、核心体验流程

```
打开网页 → 像素酒馆门面 → 点击"站到吧台后面去"

阶段1：引导（参考游戏教学）
  → 老板娘出现，教你第一句："Say hello to the guest."
  → 你说了 → 客人进来了
  → 你像缺什么突然就有什么一样，一步步被引导着开口

阶段2：对话（AI驱动）
  → 客人开口（TTS读出，有角色音色）
  → 你打字或语音回应
  → 客人根据你的话，用AI生成下一句
  → 对话中混入英语单词（精灵最明显，矮人最少）

阶段3：词汇收集
  → 你说过的英语词自动入库
  → 显示在右侧词库面板
  → 根据词库数量自动判定等级：A1(10词)→A2(30)→B1(60)→B2(100)→C1(150)

阶段4：成长与留存
  → 每日免费10枚对话币
  → 对话币用完可以买
  → 营业时间：晚7点-11点（现实时间）
  → 打烊后进不去，明天再来
```

## 三、核心功能与实现方案

### 3.1 AI 对话（灵魂）

**需求：**
- 每个 NPC 有自己的性格、说话风格
- 能理解用户说的内容，做角色扮演式回应
- 对话中自然混入英语（按角色程度不同）

**实现方案：**

| 方式 | 适用场景 | 成本 |
|:----|:--------|:----|
| **Google Gemini API**（首选） | 正式运行时 | 免费额度足够MVP |
| **关键词匹配台词库**（降级方案） | API不通时的备用 | 零成本 |
| 其他 LLM API（DeepSeek/Claude） | 可替换 | 按量计费 |

**技术细节：**
- 调用 Gemini 2.0 Flash 模型，temperature=0.9 保证创造力
- prompt 中注入角色设定 + 历史对话记录
- 回复控制在1-2句话，强制要求混入英语单词
- 备用台词库每个NPC 约30条，按5个话题分类

### 3.2 TTS 语音（NPC开口说话）

**需求：**
- NPC 的回复自动朗读出来
- 不同角色音色不同
- 语速略慢（方便跟读）

**实现方案：**
- 浏览器内置 Web Speech Synthesis API（SpeechSynthesisUtterance）
- 免费、不需要任何 API key
- 通过 rate（语速）和 pitch（音高）区分角色
- 矮人：rate=0.8, pitch=0.8（慢而低沉）
- 精灵：rate=0.85, pitch=1.1（偏快偏高）
- 商人：rate=0.9, pitch=0.95（正常略快）

**限制：** 音色选择有限，不同浏览器表现不同。更好的方案是 Edge TTS 或 Fish Audio，需要接 API。

### 3.3 语音输入（用户说话）

**需求：**
- 用户可以直接说话，不用打字
- 支持中英文混合识别

**实现方案：**
- 浏览器 Web Speech Recognition API
- 免费、不需要任何 API key
- 设置 lang='en-US,zh-CN' 支持双语
- 按住 🎤 按钮录音，松开发送

**限制：** Chrome 表现最好，Safari/Firefox 可能不稳定。后续可考虑接 Deepgram（首$200免费）。

### 3.4 词库系统

**需求：**
- 用户使用的英语单词自动收录
- 显示最近收集的单词
- 根据词库自动判定英语等级
- 词库可导出/查看

**实现方案：**

```
数据存储：localStorage（浏览器本地）
无后端，不注册，不登录

收录逻辑：
1. 检测用户输入中的英语单词（正则匹配 [a-zA-Z]{2,}）
2. 匹配预置的常用词表（约50个高频词，含中译）
3. 未匹配的单词也收录，标记为auto（翻译留空）

等级阈值：
  A1: ≥10词
  A2: ≥30词
  B1: ≥60词
  B2: ≥100词
  C1: ≥150词

展示：
  右侧面板，显示最近10个词
  左下角圆形徽章显示当前等级
```

**扩展方向：**
- 词库可导出为 Anki/CSV 格式
- 单词点击可查看例句（来自对话历史）
- 根据已掌握词汇推荐新故事难度

### 3.5 经济系统

**需求：**
- 对话消耗资源，不是无限的
- 每日赠送免费额度
- 用完可以付费购买

**实现方案：**

```
每日赠送：10枚对话币（凌晨重置）
每次对话：消耗1枚

付费购买（UI已做，支付未接）：
  20枚 → ¥3
  60枚 → ¥8
  200枚 → ¥25

存储：localStorage（token数量 + 上次重置日期）
```

### 3.6 营业时间

**需求：**
- 不是24小时都能进
- 晚7点到11点营业，和现实时间挂钩
- 打烊后用户进不去，制造稀缺感和期待感

**实现方案（尚未开发）：**
```
前端判断：获取用户本地时间
营业时段：19:00 - 23:00
非营业时段：显示"酒馆已打烊，明晚7点见"的页面
时间同步：可参考服务器时间避免用户改本地时间作弊
```

### 3.7 引导系统

**需求：**
- 用户第一次进来不知道要做什么
- 像《艾希》/《无尽冬日》那样，缺什么突然就来什么
- 开口成本降到最低

**实现方案（尚未完善）：**
```
第一步：老板娘出现，只说一句话 "Say hello to the guest."
第二步：门开了，客人进来
第三步：用户开口（打字/语音），引导完成

原则：
- 永远不显示"你是来学英语的"
- 永远不给操作手册
- 用户需要什么的时候，那个东西刚好出现
```

## 五、产品哲学

### 核心原则

```
1. AI 对话是灵魂
   关键词台词只是降级方案，核心必须是真正的AI生成。
   用户说的每一句话，NPC听到并回应。

2. 学英语是副产品，不是目标
   用户的目标是"跟客人聊天、听故事"。
   英语是在这个过程中自然习得的。

3. 开口成本无限降低
   用户不需要注册、不需要选课、不需要设置。
   打开网页 → 开口说话 → 一切发生。

4. 像素是皮肤，不是限制
   像素风不是为了省钱，是为了降低画面预期，
   让用户把注意力放在语言和故事上。
```

### 差异化定位

```
vs 流利说/有道口语 → 你是"跟客人在酒馆聊天"，不是"跟AI老师练口语"
vs Character.AI    → 你有像素世界、词库成长、营业时间
vs 剧本杀           → 你是服务员不是玩家，AI实时生成不是固定剧本
vs 米哈游           → 你一个人做的，不是几百人团队
```
